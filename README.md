# مناظرة: المرحلة 1

## التشغيل
```
npm install
npm run dev
```
للنشر لاحقًا: `npm run build` ثم انشر مجلد `dist`.

## أين أغيّر ماذا
- `src/data/system.json`: ترتيب الكلمات، أدوار المتحدثين ومهامهم، الحد الأقصى للحروف، اسم الموقع.
- `src/data/topics.json`: المواضيع. حقل `sampleSpeech` اختياري (كلمة خصم تجريبية لكل جانب).
- `src/data/rubric.json`: معايير التقييم وأسئلتها (نعم/لا) ونصائح التحسين.
- كل قيمة موسومة `TODO` مؤقتة وتُراجع في المرحلة 2.

## البنية
`pages/` الشاشات، `lib/data.ts` قراءة JSON، `lib/storage.ts` الحفظ في `localStorage`.

# المرحلة 2

## الجديد
- صفحة `السجل`: كل الجلسات، منحنى النتيجة العامة، متوسط كل معيار، وأضعف معيار.
- حفظ مسودة الكلمة تلقائيًا لكل موضوع، وتُمسح عند الانتقال للتقييم.
- تقييم الشريك: من صفحة النتيجة، تسلّم الجهاز لشخص آخر ليملأ القائمة نفسها، ثم تظهر المقارنة وأماكن الاختلاف.
- تصدير الجلسة: نسخ النص أو تنزيله ملفًا.
- بنك المواضيع: 30 موضوعًا (صياغتها تحتاج مراجعة مدرب).

## النشر المجاني
- **GitHub Pages:** ارفع المشروع (مع `package-lock.json`) إلى فرع `main`، ثم من Settings → Pages اختر Source: GitHub Actions. الملف `.github/workflows/deploy.yml` يبني وينشر.
- **Netlify أو Cloudflare Pages:** الأمر `npm run build` والمجلد `dist`.
- التوجيه يعمل بالـ hash، فلا حاجة لإعدادات إعادة توجيه.

## ما يزال معلقًا (يحتاج منك)
- مراجعة المواضيع والمعايير و`system.json` مع مدرب أو بدليل المسابقة، وإزالة وسوم `TODO`.
- اسم الموقع (`siteName` في `system.json`).
- تجربة مع 5 أشخاص من الاتحاد وجمع ملاحظاتهم.

# المرحلة 3: التقييم بالذكاء الاصطناعي (مفتاح الطالب)

- `الإعدادات`: إدخال مفتاح Gemini واسم النموذج والموافقة، وزر «اختبر» لفحص المفتاح والاتصال المباشر من المتصفح.
- `src/lib/evaluatorPrompt.ts`: تعليمات التقييم الصارمة (دليل مقتبس قبل كل إجابة، لا مديح عام، لا حكم بالفوز، تجاهل أي تعليمات داخل نص الطالب).
- `src/lib/gemini.ts`: الاستدعاء والتحقق. إن كان الاقتباس غير موجود حرفيًا في النص يظهر تنبيه.
- الزر يظهر في صفحة النتيجة، ويُحفظ الرد مع الجلسة فلا يُستهلك طلب جديد عند إعادة فتحها.
- لا يدخل تقييم الذكاء الاصطناعي في السجل ولا المتوسطات؛ هو رأي ثالث للمقارنة.

## يلزم التحقق منه يدويًا في اليوم الأول
1. زر «اختبر» ينجح (يكشف مشكلة CORS إن وُجدت).
2. اسم النموذج الافتراضي في `DEFAULT_MODEL` له مستوى مجاني في حسابك (التحقق من مصادر ثانوية فقط).
3. بلدك ضمن الدول المؤهلة للمستوى المجاني.
4. جودة الحكم بالعربية: جرّب النصوص الستة وقارن بحكم مدرب قبل الاعتماد عليه.

# تعديل: الطالب يلعب الفريق كاملًا

- عند اختيار موضوع يُفرض الموقف (مؤيد أو معارض) ويظهر في أعلى الصفحة، ولا يمكن تغييره.
- يكتب الطالب كلمات فريقه الثلاث بالترتيب في شاشة متدرجة، ولكل كلمة مربع اختياري للصق كلمة الخصم السابقة. تُحفظ المسودة تلقائيًا بما فيها الموقف المفروض.
- بعد الكلمة الثالثة تُحفظ الكلمات الثلاث كفريق واحد وتنتقل إلى `ملخص الفريق` (`/team/:id`): تقييم كل كلمة على حدة، ثم نتيجة الفريق ومتوسط المعايير وأضعفها.
- كل ما سبق (تقييم ذاتي، شريك، ذكاء اصطناعي) يعمل لكل كلمة على حدة.
- التحكم بالموقف: **أنت تفرضه لكل موضوع** من الحقل `side` في `src/data/topics.json` (`"pro"` مؤيد أو `"con"` معارض). يظهر الموقف للطالب في قائمة المواضيع وأعلى صفحة الكتابة، ولا يستطيع تغييره ولا إعادة سحبه.
- `"sideAssignment"` في `src/data/system.json`: `"topic"` (الافتراضي) يأخذ الموقف من الموضوع، وإن غاب `side` عن موضوع فيكون عشوائيًا؛ `"random"` عشوائي دائمًا؛ `"pro"` أو `"con"` يفرضان موقفًا واحدًا على كل المواضيع (مفيد للاختبارات).
- الموقف الحالي في المواضيع الثلاثين موزع بالتناوب (مؤيد ثم معارض...) كقيمة أولية، فعدّله حسب ما تريد.
- لو غيّرت `side` لموضوع، تُهمل مسودة الطالب القديمة لذلك الموضوع إن كانت بموقف مخالف.
- تنبيه: غُيّر مفتاح التخزين إلى `v2`، فالجلسات والمسودات القديمة (الكلمة المفردة) لا تظهر. لم تُحذف من المتصفح لكنها تُهمل.

# النشر الخاص بحساب دخول (مؤقت)

الموقع محمي ببوابة دخول (اسم مستخدم وكلمة مرور) على Cloudflare Pages، فلا يصل أي ملف لمن لا يملك حسابًا. الحسابات في متغير سري على Cloudflare، وليست في المستودع ولا في ملفات الموقع.

- `functions/_middleware.ts`: البوابة. إن لم يُضبط المتغير `ACCOUNTS` يُغلق الموقع كله (503) ولا يُفتح للجميع.
- `scripts/make-account.mjs`: توليد الحسابات (يدعم عدة حسابات من اليوم).
- حُذف `.github/workflows/deploy.yml`، فلا نشر على GitHub Pages (كان سيبقي نسخة علنية).

## الإعداد (مرة واحدة)
1. ارفع المشروع إلى GitHub (يصح أن يكون خاصًا).
2. في Cloudflare: Workers & Pages ← Create ← Pages ← Connect to Git، واختر المستودع.
   - Build command: `npm run build`
   - Build output directory: `dist`
   - متغير البيئة `NODE_VERSION` = `20`
3. ولّد الحساب محليًا:
   ```
   node scripts/make-account.mjs admin
   ```
   تُعرض كلمة مرور عشوائية مرة واحدة، ثم سطر JSON.
4. في المشروع على Cloudflare: Settings ← Variables and Secrets ← Add، الاسم `ACCOUNTS`، النوع **Secret**، والقيمة سطر JSON الذي طُبع. ثم أعد النشر (Deployments ← Retry deployment).
5. افتح الرابط من نافذة خاصة: يجب أن يطلب اسمًا وكلمة مرور. جرّب كلمة خاطئة أيضًا.
6. عطّل GitHub Pages من إعدادات المستودع إن كان مفعّلًا سابقًا.

## إضافة حسابات لاحقًا (عند موافقة الاتحاد)
```
node scripts/make-account.mjs <اسم>           # كلمة عشوائية
node scripts/make-account.mjs --remove <اسم>  # حذف حساب
node scripts/make-account.mjs --list          # عرض الأسماء
```
بعد كل تغيير الصق سطر ACCOUNTS الجديد في Cloudflare وأعد النشر. الملف `accounts.local.json` (hash فقط) يبقى على جهازك ولا يُرفع. احتفظ بنسخة منه.

## حدود
- نافذة الدخول هي نافذة المتصفح، ولا يوجد زر «تسجيل خروج».
- لا يوجد حد لمحاولات التخمين، لذا اترك كلمات المرور عشوائية طويلة.
- مفتاح Gemini يضعه كل مستخدم من «الإعدادات» ويبقى في متصفحه فقط.

# كلام الفريق الخصم

عند الوصول إلى كلمة لها خصم سابق (مثلًا المؤيد 1 قبل كلمة الطالب المعارض 1) يظهر كلام ذلك الخصم تدريجيًا كأن شخصًا يتكلم (زر «أظهر الكل» يختصر). ثلاثة مصادر بهذا الترتيب:

1. **الذكاء الاصطناعي** (`src/lib/opponent.ts`): إن أضاف الطالب مفتاح Gemini ووافق في «الإعدادات». نص جديد كل مرة، ويرد على ما كتبه الطالب فعلًا (المتحدث 2 يرد على كلمة الطالب الأولى...). يُحفظ مع المسودة فلا يُستهلك طلب عند إعادة فتح الصفحة. زر «كلمة أخرى» يولّد غيره.
2. **بنك النصوص**: إن لم يتوفر مفتاح أو فشل الاتصال (حد المستوى المجاني مثلًا). الحقل `opponentSpeeches` في `src/data/topics.json`:
   ```json
   "opponentSpeeches": {
     "pro": [ ["كلمة المتحدث 1", "كلمة 2", "كلمة 3"], ["نسخة ثانية 1", "2", "3"] ],
     "con": [ [...], [...] ]
   }
   ```
   يُسحب منها نسخة عشوائية، و«كلمة أخرى» تبدّلها. البنك الحالي لموضوعين فقط (`t1` و`t3`) كنماذج، وتحتاج مراجعة مدرب. أضف لبقية المواضيع بالصيغة نفسها. لا يردّ البنك على كلام الطالب لأنه مكتوب مسبقًا.
3. **اللصق اليدوي**: إن لم يوجد المصدران، يظهر حقل لصق كلمة الخصم كما كان، وهو متاح دائمًا من «عدّل أو ألصق كلمة بنفسك».

الجودة بالعربية لم تُختبر بعد مع Gemini حقيقي، فجرّب الكلمات المولّدة قبل الاعتماد عليها. تعليمات المولّد في `src/lib/opponent.ts` (`SYSTEM_INSTRUCTION`).
